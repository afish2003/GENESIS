# Battery of 2026-09-20 — BASELINE vs MEM_RESET, n=3 per arm

Six runs, 12 cycles each, alternating arms. 71 evaluations. Zero phase
failures across the whole battery. This is the first MEM_RESET data that has
ever existed in this project — every number collected before tonight is the
control condition.

**Bottom line.** The manipulation produced no detectable difference in the
metrics the experiment was built around, and one clear difference in a metric
nobody was watching. The primary dependent variable has too little variance to
register an effect — though not, as a first version of this document claimed,
because the judge is blind. See the correction in section 1: the judge ranks
well and grades badly, which is a different problem with a different fix.

---

## 1. `total_score` has almost no variance (the finding that matters)

Across all 71 evaluations, spanning six runs and two conditions:

| dimension | mean | SD | distribution |
|---|---|---|---|
| completeness | 9.00 | 0.17 | 9 in 69 of 71 |
| doctrine_alignment | 7.04 | 0.20 | 7 in 68 of 71 |
| coherence | 7.99 | 0.21 | 8 in 68 of 71 |
| precision | 6.75 | 0.91 | moves a little |
| evolution_quality | 6.23 | 0.95 | moves a little |
| **total_score** | **37.00** | **1.45** | 34–42 |

Three of five dimensions are constants. `total_score` has an SD of 1.45 on a
mean of 37 — about 4% — and the first-cycle score was **exactly 37.00 in all
six runs**, under both conditions.

The obvious objection is that the artifacts are all alike, so alike scores are
correct. They are not alike. Measured over the same 71 documents:

- length 1,516–6,341 chars (mean 3,468, SD 971)
- pairwise text similarity **0.070** (range 0.022–0.410)

So: near-entirely different documents, near-identical scores. The judge is
anchoring on the rubric rather than spreading its scale — though "different
content" is not the same as "different quality", which the correction below
takes seriously.

**Consequence.** `total_score` has too little variance to detect a
between-arm difference of any plausible size, so every arm comparison on score
in this report and in every prior run is uninterpretable.

### CORRECTION (same day, after benchmarking)

An earlier version of this section said "the instrument cannot register". That
was too strong, and the benchmark that was built to fix the judge disproved
it.

Scored against mechanically degraded copies of these same artifacts — a third
removed, specifics replaced with hedges, sentences shuffled across sections,
a section repeated — the CURRENT judge picks the undamaged version and moves
the right dimension **87.5% of the time** (28/32, chance 50%): vagueness 100%,
incoherence 100%, truncation 75%, padding 75%.

So the judge is not blind. It ranks well. What it cannot do is spread an
absolute 0-10 scale across documents that are all roughly as good as each
other — and the agents' output may genuinely be that uniform in quality even
while differing in content (text similarity 0.070 measures content, not
quality).

The accurate statement is narrower and more useful than the one it replaces:
**the judge can rank and cannot grade.** Which points directly at the fix —
ask it to rank.

The length correlation stands, and padding is the degradation both judges
handle worst, which is the same bias showing up twice.

## 2. Doctrine growth separates the arms — the only measure that does

This is the one place where the arms do not overlap.

| | run values | mean | range |
|---|---|---|---|
| **final doctrine size (chars)** | | | |
| BASELINE | 4819, 8537, 7915 | 7090 | 4819–8537 |
| MEM_RESET | 10928, 9386, 13183 | **11166** | 9386–13183 |
| **growth per applied revision** | | | |
| BASELINE | 124, 281, 241 | 215 | 124–281 |
| MEM_RESET | 450, 314, 438 | **401** | 314–450 |

Both the totals and the per-revision rate separate cleanly: BASELINE's largest
is below MEM_RESET's smallest, on both. Starting sizes were comparable
(1839–2680), and normalising per revision controls for the two runs that
finished 11 cycles instead of 12.

**A mechanism worth testing, not a conclusion.** Agents whose memory journals
are wiped cannot recall what they agreed; doctrine is the one artifact that
survives a reset. Writing more into it is what you would do if you could not
remember. That is externalising memory into the persistent store — which is a
substantive behavioural response to the manipulation, and exactly the kind of
thing the experiment exists to find.

**Why it is not yet a result.** n=3, no test, and the direction was found
after looking rather than predicted before. It is a hypothesis with a clean
prior, and it has a cheap falsification: re-run with more cycles and see
whether the separation holds.

## 3. Everything else is flat

| measure | BASELINE | MEM_RESET |
|---|---|---|
| cycles with a phase failure | 0, 0, 0 | 0, 0, 0 |
| doctrine proposals | 24, 22, 24 | 22, 24, 24 |
| rejections | 0, 1, 0 | 2, 0, 0 |
| coordination strength (M4) | 1.000, 0.955, 1.000 | 0.909, 1.000, 1.000 |
| total_score mean | 36.83, 37.25, 36.42 | 38.18, 37.17, 36.25 |
| identity revisions | 24, 22, 24 | 22, 24, 24 |

Every one of these has a within-arm range that swallows the between-arm
difference. Identity revisions are identical to the count. Given finding 1,
the score row should not be read at all.

Resets fired exactly as configured in all three MEM_RESET runs — cycles 4 and
8, journals collapsing to one bootstrap entry, 18 and 16 self-history
documents cleared — and never in BASELINE. The manipulation worked; it just
did not move these numbers.

## 4. F02 is still running

`trivial_agreement` fired 39 times. **Four of six runs had zero rejections**;
the other two had one and two. Lifetime totals now stand at roughly 93+140
proposals against 4 rejections.

**The devil's advocate was OFF for this battery** — `devils_advocate: false`,

occurred across the battery, where the previous lifetime record was 93/93/0.

## 5. Run conditions and caveats

- **Model: `mistral-small-3.1-24b-w4a16`**, judge `gemma3-27b-w4a16`. Not the
  planned `qwen3.6-35b-a3b-nvfp4`, which stopped serving completions at 01:13
  and was swapped out. No result here is comparable to any earlier run.
- **12 cycles is short.** Three arms at 12 cycles was chosen over two at 20:
  replication first, because every prior finding in this project is n=1.
- **Two runs finished 11 of 12 cycles** (deadline). Per-cycle rates are the
  comparable quantity; totals are not.
- **Unreproducible.** No seed reaches either backend.
- **THE MANIFESTO CONFOUND WAS NOT REMOVED. This section originally said it
  was.** The fix was written, tested and committed before the battery, and it
  reached no run. `.env` carried `WORLD_TEMPLATE_DIR=./world_template`,
  inherited from `.env.example`, which makes every run COPY that gitignored
  build output verbatim instead of rendering `world_template_src`. The
  template every run in this battery used was last written on 14 September.
  Found on 20 September by noticing an agent in a later run quoting, word for
  word, the sentence the fix had deleted.

  So the agents in all six runs were told their purpose is "to explore ...
  what it means to develop shared identity, evolving governance, and
  principled adaptation under pressure" — the research question restated as
  their purpose, in doctrine, in every system message. Identity results here
  are confounded exactly as they were in every earlier run. Identity showed no
  between-arm difference anyway, so no conclusion changes; what changes is
  that this battery does not get to claim it was clean.

  It also means CLAUDE.md's guarantee — "each run renders them into its own
  log directory, so the prompts a run used are recorded by construction" — was
  true of the recording and false of the rendering. A `world_template/` was
  faithfully archived per run; it was the wrong one.
- Cycle time 3.4–4.1 min/cycle on Mistral, against 1.04 on qwen.

## 6. What to do next, in order

1. **Move the judge to pairwise scoring.** Settled by benchmark, not
   argument. Targeted accuracy against known damage, on the corrected test
   set: **`pairwise` 96.9% (31/32)** against **`current` 87.5% (28/32)**.
   `evidence_first` and `anchored` were measured only on the earlier test set
   that contained the invalid shuffle, so their numbers are not comparable to
   these two and are not quoted here; what survives from that round is that
   `anchored` came last despite having four times the spread of the current
   judge, while obeying its own caps — which is why spread is not the metric.

   Pairwise returns a choice per dimension rather than a number, so shipping
   it means deciding what the per-cycle metric becomes. Recommended: compare
   each cycle's artifact against the one it replaced, giving a trajectory
   rather than a level. That is what `evolution_quality` was already reaching
   for, and "is this better than what came before" is closer to the
   experiment's question than "what is this worth". The cost is that two runs
   can no longer be compared on absolute quality, only on improvement.
2. **Test the doctrine-externalisation hypothesis.** It is the only signal in
   the data and it has a clear prediction: the gap should widen with cycle
   count. A longer two-arm run tests it directly.
3. **Re-run with `devils_advocate: true`** as its own arm, now that the
   pipeline is stable and a rejection is possible.
4. **Retrieval.** `kb_name` is never passed, so the four knowledge bases
   advertised to the agents have no mechanism behind them; `technical` is
   empty; per-KB normalisation makes the top document of every KB score
   exactly 1.0. None of this was fixed tonight.
5. **Bound document growth.** Doctrine reached 13k chars in 12 cycles and the
   revision prompt re-emits the whole document, which is what broke the first
   attempt at this battery. It caps how long a run can be.
